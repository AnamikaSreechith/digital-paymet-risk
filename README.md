### Digital Payment Risk & Fraud Detection ###

An end-to-end machine learning project that analyzes payment transaction data and identifies potentially fraudulent transactions using an XGBoost classification model. The project includes data exploration, model development and evaluation, SHAP-based explanations, and an interactive Streamlit dashboard.

## Project Overview ## 
The application accepts a transaction CSV, validates the required input columns, applies the saved preprocessing scaler, and predicts the fraud probability for each transaction.

The current application is built and trained around the Kaggle Credit Card Fraud Detection dataset. It is not a plug-and-play model for arbitrary payment datasets: uploaded files must contain the same feature schema and compatible preprocessing used to train the model.

# Key Features #
- Fraud prediction: Uses a trained XGBoost classifier to estimate the probability that a transaction is fraudulent.

- Adjustable-in-code decision cutoff: Uses a decision threshold of 0.97 to classify transactions as fraudulent or genuine.

- Risk categorization: Displays Low, Medium, or High Risk based on the model's predicted fraud probability.

- Dataset upload and validation: Accepts CSV files and checks for the required feature columns and numeric values.

- Detection overview: Summarizes total transactions, predicted fraudulent transactions, genuine transactions, and the fraud detection rate.

- Interactive analytics: Visualizes transaction classification and risk-level distribution.

- Transaction search and filtering: Search by transaction ID, amount, time, prediction, or risk level; filter by Genuine or Fraudulent status.

- Paginated transaction table: Browse large uploaded datasets in manageable pages.

- Individual transaction details: Inspect the amount, fraud probability, risk level, and prediction for a selected transaction.

- SHAP explainability: View the strongest feature contributions for an individual prediction, including signals that push the model output towards or away from fraud.

- CSV exports: Download the complete prediction report or only the currently filtered transactions. The reports use reader-friendly fields and omit anonymized PCA columns (V1–`V28`).


# Model #
- Algorithm: XGBoost classifier
- Saved model: models/final_xgboost_model.pkl
- Saved scaler: models/standard_scaler.pkl
- Decision threshold: 0.97
- Model input size: 30 features
Required CSV columns
The uploaded CSV must contain these 30 numeric columns, in the expected schema:
- Time
- V1, V2, ... V28
- Amount


Important: V1–`V28` are anonymized PCA-transformed components supplied by the original dataset. They are not human-readable transaction attributes such as merchant, cardholder, device, or location. Their negative or positive values are mathematical component values, not indicators of good or bad transactions by themselves.

## Setup and Installation ##

1. Clone the repository
git clone <your-repository-url>
cd Digital-Payment-Risk-Fraud-Detection
If you already have the project locally, open its project folder in VS Code instead.
2. Create and activate a virtual environment
Windows PowerShell:
python -m venv venv
.\venv\Scripts\Activate.ps1
3. Install dependencies
python -m pip install --upgrade pip
pip install -r requirements.txt
4. Check the required model files
Make sure these files exist:
models/final_xgboost_model.pkl
models/standard_scaler.pkl
The application loads these saved artifacts when it starts. They are not generated by running app.py.
5. Run the Streamlit application
From the project root directory:
streamlit run app.py
Streamlit will display a local URL in the terminal, usually:
http://localhost:8501
Open that address in your browser.

# How to Use the Application #
1. Start the Streamlit application.
2. Upload a CSV containing the required 30 input features.
3. Review the detection overview and risk analytics.
4. Search for transactions or filter the table by Genuine or Fraudulent status.
5. Browse the paginated results and select a transaction to inspect its details.
6. Expand Why did the model make this decision? to view the SHAP explanation.
7. Download either the full prediction report or the filtered transaction report.

# Understanding the SHAP Explanation #
The individual SHAP chart shows how selected input features influenced the model output for one transaction:
- Pink bars: Contributions that push the model output towards the fraud class.
- Green bars: Contributions that push the model output away from the fraud class.
- Longer bars: Larger contribution magnitude for that prediction.
SHAP values describe model contributions. They are not fraud probabilities, and they do not prove that a transaction is fraudulent. Since V1–`V28` are anonymized PCA components, the chart explains the model's mathematical inputs rather than identifying real-world causes.
Important Notes and Limitations

- The current trained model is designed for the feature format of the Kaggle Credit Card Fraud Detection dataset.
- A different payment dataset may use different columns, units, encodings, or preprocessing. It cannot be reliably analyzed by this model just by uploading it; a compatible data-mapping and preprocessing pipeline, and potentially model retraining, would be required.
- The 0.97 decision threshold is the threshold configured in the current application. Changing it affects the fraud/genuine classification.
- Predictions are model outputs for analysis and should not be treated as a definitive finding of fraud or as a replacement for a payment provider's risk controls.
- The app creates transaction IDs (TXN-000001, etc.) based on row order in the uploaded file.
